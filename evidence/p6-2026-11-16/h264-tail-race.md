# H.264 1080p 短输出定向复现（2026-11-16）

过夜负载末轮出现 1 次 H.264 300 帧只解出 299 帧
（[soak-overnight-v020.md](soak-overnight-v020.md)）。本记录是随后对该次
失败的定向复现尝试，**没有复现到**。

## 内容

脚本为仓库内 [scripts/h264-tail-race.sh](../../scripts/h264-tail-race.sh)，
与过夜负载中的 H.264 步骤同一输入、同一参数：

- `p5/h264-1080p-baseline.mp4`，1080p，300 帧；
- `h264_v4l2m2m`，`-num_capture_buffers 10`，输出 `framemd5`；
- 每次与 `p5/h264-1080p-baseline.md5` 逐帧比较；
- 帧数不足时记录首个差异行（用于区分"丢帧"与"改帧"），并保留该次
  `framemd5`。

## 结果

```
200 ok 300
short=0 mismatch=0
```

[原始日志](h264-tail-race.log) 共 202 行：200 行 `N ok 300`，末两行为汇总与
`RACE_DONE`。日志末行的 `ok=` 字段在机上是脚本里 `grep -c '\x27 ok \x27'`
的引号写法产生的字面量（计数恒为 0），实数为 200 次 `ok 300`；仓库内脚本
已改为 `grep -c ' ok '`。

## 结论

- 200 次重复全部 300/300 且逐帧哈希与软件参考一致，失败**不能按需复现**。
- 加上过夜窗口的 1524 次 H.264 300 帧解码，累计 1724 次中出现 1 次，
  约 0.06%。这个区间只能说明它稀有，样本不足以给出稳定概率或定位。
- 失败是**短输出**（299 帧），不是内容不符；当时 54 °C、CmaFree 44 MB、
  MemAvailable 530 MB、两个设备都在，因此不是资源耗尽或热降频的表象。
- 根因**未确定**。目前的观察与"EOS 时最后一帧偶发未从固件返回"一致，
  但没有证据排除客户端取帧时序；需要在复现到时保留首个差异行与整段
  dmesg，或加驱动侧计数（固件完成 vs 交付到用户态）才能分辨。
- 不因此修改驱动：没有复现样本时改动等于盲改，且会削弱现有 7620 轮
  0.07% 基线的可比性。
