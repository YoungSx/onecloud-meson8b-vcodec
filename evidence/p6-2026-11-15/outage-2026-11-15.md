# 2026-11-15 复位与 USB 存储失效

在役机在原内核 `5.15.79-meson` 上复位后，`/mnt/sda2`（USB 磁盘，`uas`，
120 GB）不再枚举。Docker（`data-root=/mnt/sda2/opt/docker`）、SublinkPro
与 VoCat 都依赖该盘，三者随盘离线。编解码栈与复位无因果关系，复位后已
复测可用。

## 日志时间不可用

该机无 RTC。启动时 `systemd-timesyncd` 报告
`System clock time unset or jumped backwards, restoring from recorded
timestamp`，复位时 `system.journal` 被判为 `corrupted or uncleanly shut
down, renaming and replacing`。结果是同一批启动日志里出现互相矛盾的时间戳：
`kern.log` 有两条 `Booting Linux`（22:37:41 与 23:00:59），但 soak 期间内核
单调时钟已到 `167239 s`（约 46 小时），与任何「刚启动 3 分钟」的时间戳都不
自洽。

因此**本记录不给出复位次数与时刻**，只列能独立核实的事实。

## 可核实的事实

| 事实 | 依据 |
| --- | --- |
| USB1 端口 1 长期报 `usb_submit_urb returned -121`（EIO） | `kern.log.1` 按日计数 11-12 461 条、11-13 487 条、11-14 367 条；11-15 另有 401 条 |
| 这些错误早于本轮任何 codec 操作 | 最早的 `-121` 在 11-14 00:12 |
| soak 在第 191 轮后停止，未写完成行 | `soak-30min.log` 末行为 `iter=191`，无 `SOAK_DONE` |
| 未见内核崩溃 | 无 `Oops`/`BUG:`/`panic`/`soft lockup`/`hard LOCKUP`/OOM；`pstore` 为空；`panic_on_oops=0`、`panic=0` |
| 最后一次启动后 USB 磁盘不枚举 | 见下节 |
| 编解码栈复位后自恢复并可用 | 见末节 |

## USB 磁盘

最后一次启动后，USB1 端口 1 每次枚举都失败：

```
usb 1-1: new full-speed USB device number 2 using dwc2
usb 1-1: device descriptor read/64, error -71
usb 1-1: new full-speed USB device number 3 using dwc2
usb 1-1: device descriptor read/64, error -71
usb usb1-port1: attempt power cycle
```

`error -71` 是协议层错误（EPROTO），内核 power cycle 之后不再重试。
已尝试且无效：`dwc2` 控制器 unbind/bind（两次）、root hub unbind/bind、
`uas` 重新加载、端口 `authorized` 复位、端口 `uevent` 重发、手动
`systemctl start mnt-sda2.mount`（超时）。`uas` 与 `usb-storage` 均已加载，
`/dev/sd*` 不存在，`/proc/scsi/scsi` 为空，`/dev/disk/by-uuid` 只有 eMMC 的
两个分区。dwc2 已处于 host 模式、端口显示已连接，但描述符读取失败。

同一块盘在 11-14 00:12 的启动日志里也是 `new full-speed USB device`，
即长期以全速（12 Mbps）链路工作，并从 11-14 起持续报 `-121`。全速枚举、
间歇性 EIO、复位后彻底不识别，指向磁盘本体、USB 线材或供电，而不是
codec 模块。同一控制器下 USB2 的智能卡读卡器枚举正常，问题集中在
USB1 端口 1 与这块盘。

eMMC 上没有可用的替代数据根：`/opt/wanos-data/docker` 只有 8 KB，
`/opt/vocat` 是指向 `/mnt/sda2` 的符号链接。根分区已用 83%（1.2 GB 可用），
无法容纳原数据。

## 复位后的编解码状态

`meson8b-vcodec.service` 自动恢复，模块与设备正常：

| 项目 | 结果 |
| --- | --- |
| `/dev/video0`、`/dev/video1` | 存在 |
| HEVC 1080p 硬解 | 通过 |
| H.264 10 帧编码 | PASS |
| JPEG 3 帧编码 | PASS |
| stop → start 循环 | 通过，无 `OF: ERROR` 或 refcount 告警 |

## 结论与待办

- 编解码栈在复位后自恢复并通过功能复测；没有证据表明 codec 模块导致复位。
- 生产服务当前不可用，原因是 USB 磁盘未枚举。需现场处理：重新插拔、更换
  USB 线或供电、检查磁盘本体；若磁盘损坏则从备份恢复 `/mnt/sda2`。
- 磁盘恢复前 `docker.service`、`sublinkpro.service`、`vocat.service` 保持
  inactive，`mnt-sda2.mount` 的 start job 挂在
  `dev-disk-by-uuid-584c4a88-….device` 上。
- soak 的 30 分钟/2 小时/过夜验收需在磁盘与供电问题处理后重做。
