# 2026-11-15 夜间两次硬复位与 USB 存储失效

在役机在原内核 `5.15.79-meson` 上连续两次硬复位，复位后 `/mnt/sda2`
（USB 磁盘，`uas`，120 GB）不再枚举。Docker（`data-root=/mnt/sda2/opt/docker`）、
SublinkPro 与 VoCat 都依赖该盘，三者随盘离线。编解码栈与复位无因果关系，
复位后已复测可用。

## 时间线（+08:00）

| 时刻 | 事件 |
| --- | --- |
| 11-14 00:12 起 | `usb 1-1: usbfs: usb_submit_urb returned -121`（-121 = EIO）持续出现 |
| 11-15 20:42–21:51 | 同类 USB 错误密集出现（数百条），早于任何本轮 codec 测试 |
| 22:40:52 | 30 分钟 soak 开始，191 轮 `FAILS=0` |
| 22:54:18 | soak 最后一轮；此后脚本无输出、进程消失 |
| 22:57:48 | `meson8b-vcodec.service` 重新加载三个模块 |
| 22:37:41 / 23:00:59 | 两次内核启动（kern.log 中两条 `Booting Linux`） |
| 23:01:09 | 上一次启动的 journal 结束，无 shutdown/reboot 记录 |

两次复位都没有 `Oops`、`BUG:`、`panic`、`soft lockup`、`hard LOCKUP`、OOM 或
`systemd-logind` 关机请求，`pstore` 为空（ramoops 已加载但无转储），
`panic_on_oops=0`、`panic=0`。属于掉电/硬件级复位，而不是内核崩溃。

## USB 磁盘

复位后 USB1 端口每次枚举都失败：

```
usb 1-1: new full-speed USB device number 2 using dwc2
usb 1-1: device descriptor read/64, error -71
usb 1-1: new full-speed USB device number 3 using dwc2
usb 1-1: device descriptor read/64, error -71
usb usb1-port1: attempt power cycle
```

`error -71` 是协议层错误（EPROTO），随后内核尝试 power cycle 后不再重试。
已尝试且无效：`dwc2` 控制器 unbind/bind（两次）、root hub unbind/bind、
`uas` 重新加载、端口 `authorized` 复位。`uas` 与 `usb-storage` 均已加载，
`/dev/sd*` 不存在，`/proc/scsi/scsi` 为空，`/dev/disk/by-uuid` 只有 eMMC 的
两个分区。

同一磁盘在 11-14 00:12 的启动日志里同样是 `new full-speed USB device`，
说明它长期以全速（12 Mbps）链路工作，且从 11-14 起持续报 `-121`。全速枚举、
间歇性 EIO、复位后彻底不识别，指向磁盘本体、USB 线材或供电，而不是
codec 模块。

## 复位后的编解码状态

`meson8b-vcodec.service` 自动恢复，模块与设备正常：

| 项目 | 结果 |
| --- | --- |
| `/dev/video0`、`/dev/video1` | 存在 |
| HEVC 1080p 硬解 | 通过 |
| H.264 10 帧编码 | PASS |
| JPEG 3 帧编码 | PASS |

## 结论与待办

- 编解码栈在两次复位后自恢复并通过功能复测；没有证据表明 codec 模块导致复位。
- 生产服务当前不可用，原因是 USB 磁盘未枚举。需要现场处理：重新插拔/更换
  USB 线或供电、检查磁盘本体；若磁盘损坏则从备份恢复 `/mnt/sda2`。
- 在磁盘恢复前，`docker.service`、`sublinkpro.service`、`vocat.service`
  保持 inactive，`mnt-sda2.mount` 的 start job 仍挂在
  `dev-disk-by-uuid-584c4a88-….device` 上。
- soak 的 30 分钟/2 小时/过夜验收需在磁盘与供电问题处理后重做。
