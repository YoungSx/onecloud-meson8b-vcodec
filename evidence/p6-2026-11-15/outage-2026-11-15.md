# 2026-11-15 夜间两次硬复位与 USB 存储失效

在役机在原内核 `5.15.79-meson` 上连续两次硬复位，最后一次复位后 `/mnt/sda2`
（USB 磁盘，`uas`，120 GB）不再枚举。Docker（`data-root=/mnt/sda2/opt/docker`）、
SublinkPro 与 VoCat 都依赖该盘，三者随盘离线。编解码栈与复位无因果关系，
复位后已复测可用。

## 时间不可靠的前提

该机无 RTC。启动时 `systemd-timesyncd` 把时钟恢复成记录时间戳，日志中可见
`System clock time unset or jumped backwards, restoring from recorded
timestamp`。第一次复位时时钟向后跳了约 7 分钟，两次启动的墙钟区间因此重叠，
`syslog`/`kern.log` 的行首时间无法用来排序。另外 `system.journal` 在复位时
被判为 `corrupted or uncleanly shut down`，中间那次启动的 journal 不完整。

因此本记录只用**能独立核实**的事实，不拼凑完整时间线。

## 可核实的事实

| 事实 | 依据 |
| --- | --- |
| 11-12 起 USB1 端口 1 持续报 `usb_submit_urb returned -121`（EIO） | `kern.log.1` 按日计数 461 / 487 / 367 条，11-15 另有 401 条 |
| 这些错误早于本轮任何 codec 操作 | 最早的 `-121` 出现在 11-14 00:12 |
| 11-15 出现两次内核启动 | `kern.log` 中两条 `Booting Linux on physical CPU 0x200` |
| 30 分钟 soak 在第 191 轮后停止，未写完成行 | `soak-30min.log` 末行为 `iter=191`，无 `SOAK_DONE` |
| 两次启动都没有内核崩溃 | 无 `Oops`/`BUG:`/`panic`/`soft lockup`/`hard LOCKUP`/OOM；`pstore` 为空；`panic_on_oops=0`、`panic=0` |
| 最后一次启动后 USB 磁盘不枚举 | 见下节 |
| 编解码栈复位后自恢复并可用 | 见末节 |

soak 停止与复位之间的先后关系只能从日志内部顺序推断，不能给出可靠时刻。

## USB 磁盘

最后一次启动后，USB1 端口 1 每次枚举都失败：

```
usb 1-1: new full-speed USB device number 2 using dwc2
usb 1-1: device descriptor read/64, error -71
usb 1-1: new full-speed USB device number 3 using dwc2
usb 1-1: device descriptor read/64, error -71
usb usb1-port1: attempt power cycle
```

`error -71` 是协议层错误（EPROTO），内核 power cycle 之后不再重试。
已尝试且无效：`dwc2` 控制器 unbind/bind（两次）、root hub unbind/bind、
`uas` 重新加载、端口 `authorized` 复位。`uas` 与 `usb-storage` 均已加载，
`/dev/sd*` 不存在，`/proc/scsi/scsi` 为空，`/dev/disk/by-uuid` 只有 eMMC 的
两个分区。

同一块盘在 11-14 00:12 的启动日志里也是 `new full-speed USB device`，
即长期以全速（12 Mbps）链路工作，并从 11-14 起持续报 `-121`。全速枚举、
间歇性 EIO、复位后彻底不识别，指向磁盘本体、USB 线材或供电，而不是
codec 模块。同一控制器下 USB2 的智能卡读卡器枚举正常，问题集中在
USB1 端口 1 与这块盘。

## 复位后的编解码状态

`meson8b-vcodec.service` 自动恢复，模块与设备正常：

| 项目 | 结果 |
| --- | --- |
| `/dev/video0`、`/dev/video1` | 存在 |
| HEVC 1080p 硬解 | 通过 |
| H.264 10 帧编码 | PASS |
| JPEG 3 帧编码 | PASS |
| stop → start 循环 | 通过，无 `OF: ERROR` 或 refcount 告警 |

## 结论与待办

- 编解码栈在两次复位后自恢复并通过功能复测；没有证据表明 codec 模块导致复位。
- 生产服务当前不可用，原因是 USB 磁盘未枚举。需要现场处理：重新插拔/更换
  USB 线或供电、检查磁盘本体；若磁盘损坏则从备份恢复 `/mnt/sda2`。
- 磁盘恢复前 `docker.service`、`sublinkpro.service`、`vocat.service` 保持
  inactive，`mnt-sda2.mount` 的 start job 挂在
  `dev-disk-by-uuid-584c4a88-….device` 上。
- soak 的 30 分钟/2 小时/过夜验收需在磁盘与供电问题处理后重做。
