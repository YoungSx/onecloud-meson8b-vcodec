# S805 厂商能力追平

目标分为格式、内容、标准接口、数据路径和吞吐。固定厂商源码为 Hardkernel
`5aed95d35d252cafc75ce613a3a0052285662de2`；不把其他 Meson 芯片的实现
当作 S805 能力。迅雷出厂固件的配置与同机基准尚缺，当前唯一设备为在役
WanOS，无备用板/串口。新增硬件路径先完成工作机实现和边界/构建检查，
保持未部署；不修改启动文件或用生产持续压力替代取证。

## 当前执行顺序

1. 性能拆分；GE2D 字节序/缓冲自检通过后，继续裁剪、NV12 缩放和 DMA 生命周期。
2. HEVC tiles，覆盖均匀/非均匀、slice、MV 与滤波。
3. H.263、WMV3 等有固件依据的格式，再处理 MPEG/VC-1 完整性。
4. 单 HCODEC 多会话调度及资源预算；严格区分实例数与总吞吐。
5. 对相同输入、质量、内存条件完成厂商路径与移植的硬件内容/性能对照。

历史 H.264 #5 调查保持开放，按用户选择暂停主动复现。没有适用于 S805 的
HEVC 编码、Main10 或可靠高级 H.264 编码路径时，不添加虚假的能力枚举。
AVS 标准 UAPI/应用落点、WMV3 Annex L/RCV 封装也必须明确后再开放格式。

## 工作机已完成的新增源码

| 项目 | 实现 | 验证与边界 |
| --- | --- | --- |
| 阶段测量 | 原 argv、有界超时、CPU/CMA、计数差值、独立完整软解 | 主机错误注入及实际软件命令通过；视频帧数/可选哈希，音频与有损质量另外验收。 |
| GE2D | 独立标准 GREY M2M、canvas、源/目标 endian、probe 字节图案自检 | 实际命令 MMIO 测试、DMA 越界/超时/复位回归与 ARM 构建；没有实机像素，未接替 NEON。 |
| HEVC tiles | 标准均匀余数分配、最多 5×5 网格、有界尺寸、MPRED rectangle/row jump/new tile、跨 tile 滤波 | 几何和实际 MPRED/SAO 函数 ASan/UBSan、ARM 构建；4×2 1080p 和 3×2 非均匀流由独立软件解码，候选未实机。 |
| H.263 | 固定 h263_mc、标准 H263、MPEG-4 共用 mailbox/帧池、picture header、离散尺寸、EOS | 独立 C 固件字节比对、头部/协商尺寸及 EOS 失败回归、ARM 构建；baseline I/P，无 PLUS/custom/可选工具，尾帧和内容未实机。 |

HEVC tile 几何遵守 H.265 均匀分区，例如 30 CTU/4 列为 `7/8/7/8`，
不复制厂商旧 `7/7/7/9`。RPM 的非均匀宽/高按厂商值读取，最后一列/行由
图像总尺寸推导；微码参数与真实 slice 内容仍需要 S805 样片验收。
SAO scratch 保留厂商的整图大小/基地址协议，按列/行检查容量；不把仅有
源码计算的 tile scratch 地址写成一个未经验证的新协议。

## 已部署模块的短时性能快照

2026-11-23 使用当前在役 `3c7d785` codec、原 `5.15.79-meson`/64 MiB CMA，
模块没有切换。固定 1080p 静态彩条、30 fps、60 图（2 s）：

- H.264 硬解→4 Mbps H.264 硬编，完整软解为 60/60，命令墙钟约 4.052 s，
  约 0.494×；转换累计 558 ms，输入拷贝 248 ms，无 DMA-BUF 直读。
- null 输出下，FFmpeg 内部解码耗时 1.653 s、60 图；命令总墙钟 2.366 s。
  加 `scale=1280:720` 后，内部耗时 5.023 s、60 图，命令总墙钟 5.882 s，
  子进程 CPU 约 7.369 s。输出完整计数不代替像素/质量验收。
- 原始视频写入 tmpfs 的对照为 10.008/7.393 s，包含 rawvideo 编码与 I/O，
  不用于硬件吞吐判断。转换计数约 7–14 ms/帧，负载差异明显。

这些是同一静态源的有界测量，没有音频/HLS，也非满吞吐、画质比较或新的
稳定性验收。缩放 CPU 开销有直接测量依据，GE2D 优先验证该收益；不能从
计数相加预测实际加速。原件在忽略报告目录，当前没有永久公开附件。

工具入口见[阶段测量](performance.md)，精确已安装来源见[部署快照](rollout-status.md)。
